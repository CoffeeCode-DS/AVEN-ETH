# AVEN-ETH

A prototype blockchain-inspired freelance escrow platform. A **Client** hires a **Freelancer**, funds a project into a simulated escrow, and payment is released automatically once the work is reviewed and approved.

> **Simulation Mode.** No real wallets, no real ETH, no real blockchain network. Every "transaction" is generated by the app's own simulation service (fake tx hash, block number, network name) so the experience *feels* like a Web3 escrow product without any real financial risk.

---

## Overview

AVEN-ETH walks a project through a full escrow lifecycle:

```
CLIENT creates an agreement → selects a freelancer → sets budget & deadline
        ↓
CLIENT funds escrow (simulated)
        ↓
FREELANCER starts the project → tracks time in a work session
        ↓
FREELANCER submits work for review
        ↓
CLIENT reviews: Approve & Release · Request Revision · Reject
        ↓
   (if revision requested, freelancer reworks and resubmits)
        ↓
CLIENT approves → simulated payment released → agreement COMPLETED
```

Every step updates a real backend state machine, creates a transaction record, and fires a notification — nothing on screen is fake or disconnected.

## Features

- **Two distinct role-based experiences.** Client and Freelancer see different navigation, different dashboards, and different actions — enforced on both the frontend *and* the backend (a Freelancer token physically cannot call the "fund escrow" endpoint, regardless of what the UI shows).
- **Full agreement lifecycle** with a real state machine (`PENDING_FUNDING → FUNDED → IN_PROGRESS → SUBMITTED → COMPLETED`, with a `REVISION_REQUESTED` loop back to `IN_PROGRESS`, and a `CANCELLED` terminal state for rejections). Invalid transitions (e.g. approving a project twice) are rejected with a 409.
- **A genuine, lightweight blockchain simulation** — every escrow event (funding, submission, revision, payment release) mines a real block: a real SHA-256 proof-of-work search (difficulty 3, a few thousand hashes, milliseconds), a real previous-hash link to the block before it, and a real nonce. Nothing is a fabricated string.
- **Blockchain ledger page** showing the entire chain, block by block, each one visually connected to the next with its real hash, previous hash, nonce, and difficulty.
- **Security & Consensus page** with an interactive "Run Security Verification" check (recomputes every hash and every link live, not a canned animation) and a "Tamper Detection Demo" — deliberately corrupt a block's data and watch verification catch exactly where the chain breaks, then restore it.
- **Smart Contract panel** on every agreement showing the escrow contract's live state (locked / released / remaining balance, wallet addresses, and a conditions checklist), always derived from real agreement data.
- **Transaction detail view** — click any transaction for an expandable breakdown: overview, participants, full blockchain data (block number, hash, previous hash, nonce, difficulty, consensus method), and a confirmation timeline.
- **Work session timer** — start / pause / resume / stop, with time accumulated server-side (not just in the browser), plus estimated earnings based on the freelancer's hourly rate.
- **Real notifications** tied to actual events, with unread counts and click-through navigation.
- **Realistic seed data** — Sarah Chen (client) and Marcus Rivera (freelancer) with three agreements in three different states, so both dashboards look alive on first login. Seed transactions are mined onto the real chain at startup too, so the Transactions page and the Blockchain page are never showing two disconnected sets of numbers.
- **A premium, responsive UI** — dark navy sidebar, electric-blue accent, IBM Plex Mono for on-chain data, an animated "escrow pulse" motif for the Client → Escrow → Freelancer flow, loading skeletons, empty states, and full mobile support with a slide-out nav drawer.

## Architecture

```
aven-eth/
├── server/                  Express API (backend)
│   └── src/
│       ├── data/            In-memory repository layer + seed data
│       ├── middleware/      JWT auth + role-based authorization
│       ├── routes/          REST endpoints
│       ├── services/        Business logic: escrow state machine,
│       │                    the SimulationService, notifications
│       ├── utils/           Simulated tx hash/block/receipt generation
│       └── tests/           node:test unit/integration tests
│
└── client/                  React + Vite (frontend)
    └── src/
        ├── api/              Typed fetch wrapper around the backend
        ├── components/       Reusable UI (cards, modals, badges, etc.)
        ├── context/          Auth + Toast providers
        ├── layouts/          App shell (sidebar + topbar)
        ├── pages/            One file per route
        └── utils/            Formatting helpers
```

The backend is intentionally architected so the in-memory data store and the `SimulationService` sit behind clean interfaces — the app is described in the code as ready to swap the simulation layer for a real Ethereum/Sepolia integration later without touching route handlers, and the in-memory store for a real MongoDB collection without touching business logic. For this prototype, everything runs in memory so there's zero database setup required.

### How the blockchain simulation actually works

`server/src/services/blockchainService.js` maintains an in-memory chain starting from a mined genesis block. Every time `escrowService.js` records a transaction, it calls `blockchain.mineBlock(...)`, which:

1. Takes the previous block's hash.
2. Serializes the new block's contents (type, agreement, amount, parties, timestamp).
3. Searches for a `nonce` such that `SHA-256(contents + nonce)` starts with 3 hex zeros — real proof-of-work, just tuned to a difficulty that resolves in milliseconds rather than wasting real compute.
4. Appends the mined block to the chain and returns it.

The resulting hash, previous hash, nonce, and difficulty are stored directly on the transaction record — the UI never fabricates these numbers itself. `GET /api/blockchain/verify` walks the entire chain, recomputes every block's hash from its stored fields, and checks every previous-hash link, so "chain integrity" is a real, live computation rather than a static label.

## Tech Stack

**Backend:** Node.js, Express, JWT (`jsonwebtoken`), an in-memory repository layer (no database server to install), `node:test` for tests.

**Frontend:** React 18, React Router, Vite, Tailwind CSS. No external UI kit — every component (buttons, modals, badges, cards) is hand-built to match the app's design system.

## Installation

**Requirements:** Node.js 18+ and npm.

From the project root:

```bash
npm install
```

This installs the root tooling (`concurrently`) and, via a `postinstall` hook, automatically installs both `server/` and `client/` dependencies. If you'd rather do it by hand:

```bash
npm install --prefix server
npm install --prefix client
```

## Environment Setup

No environment variables are required to run the app — it works immediately with sensible defaults. If you want to override anything, copy the example files:

```bash
cp server/.env.example server/.env
cp client/.env.example client/.env
```

`server/.env` lets you override the port (`PORT`, default `4000`) and the JWT signing secret (`JWT_SECRET`). The client needs no variables at all — the Vite dev server proxies `/api` straight to the backend.

## Running the App

From the project root, one command starts both the API and the web app together:

```bash
npm run dev
```

- Backend API → `http://localhost:4000`
- Frontend → `http://localhost:5173`

Open `http://localhost:5173` in your browser. That's it.

**Running them separately**, if you prefer two terminals:

```bash
npm run dev:server   # http://localhost:4000
npm run dev:client   # http://localhost:5173
```

**Production build** of the frontend:

```bash
npm run build
```

## Running Tests

```bash
npm test
```

This runs the backend test suite (`node --test`, 15 tests across two files), covering the full agreement lifecycle, the revision loop, the reject path, invalid state transitions, authorization boundaries, input validation, and the blockchain layer itself — real proof-of-work mining, chain linking, tamper detection, and restore. All tests reset both the in-memory database and the chain between runs, so they're fully independent.

## Simulation Mode

**This is a prototype. No real money, cryptocurrency, or blockchain network is ever involved.** Every ETH value on screen — escrow balances, budgets, payments — is a simulated demo number. Every "transaction" (escrow funding, payment release, etc.) is generated by `server/src/utils/simulate.js` and `server/src/services/escrowService.js`, producing a fake transaction hash (`0xSIM...`), an incrementing fake block number, and a `AVEN-ETH Simulation Network` label. Nothing in the app ever claims a real on-chain event occurred, and no wallet connection (MetaMask or otherwise) is required or used.

## Complete Demo Workflow

To see the entire platform in action:

1. **Log in as Client** (`client@aven.dev`) → see the dashboard with active projects, escrow stats, and pending reviews.
2. **Create a new agreement** — walk through the 5-step wizard (project details → select freelancer → budget → deadline → review) and create it.
3. **Fund escrow** on the new agreement — confirm in the modal; the escrow balance updates immediately and Marcus gets a notification.
4. **Log out, log in as Freelancer** (`freelancer@aven.dev`) — see the newly funded project, click **Start Project**.
5. **Go to Work Sessions**, start the timer, do some "work," then **Stop Session** and fill out the submission form (summary + deliverables), then **Submit for Client Review**.
6. **Log out, log in as Client** — see the notification, open the agreement, and either:
   - **Approve & Release Payment** → escrow releases, a payment transaction is created, the agreement becomes `COMPLETED`, or
   - **Request Revision** → leave feedback; the freelancer will see it and can rework + resubmit.
7. **Check Transactions** — every step above left a transaction record with a real mined block: hash, previous hash, nonce, and difficulty. Click any transaction to see its full blockchain data.
8. **Check the Blockchain page** — the same events, shown as a connected chain of blocks from genesis onward.
9. **Visit Security & Consensus** — click **Run Security Verification** to watch a live recomputation of every hash and link in the chain, or try the **Tamper Detection Demo**: corrupt a block, watch verification fail at exactly that block, then restore it.
10. **Check Notifications** — every step above also left a notification for the relevant party.

Every number shown on screen throughout this flow comes directly from backend state — nothing is hardcoded or faked on the frontend.
